- **한 번에 변수 하나만 바꾼다.** 두 개를 동시에 바꾸면 "무엇이 얼마나 올렸다"고 말할 수 없다.

## 핵심 결론 (09/23)

1. **이 문제는 글자 판독 문제지만, 가장 잘 읽는 OCR은 VLM 자신이다.** 외부 OCR 단독 49% vs VLM 93%+.
2. **입력 보강(OCR 주입 · 고해상도)은 모델이 강해지면 효과가 사라진다.**
   OCR 주입: 768 제로샷 +1.2%p → 1024 제로샷 +0.25%p → 1024 학습 −0.1%p. 해상도: 8B 제로샷 +0.8%p → 32B 학습 −0.35%p.
3. **앙상블에는 센 모델보다 다르게 틀리는 모델이 필요하다.** 7B 제로샷(0.9215)을 7B 학습본(0.9490)으로 바꾸면 앙상블이 0.9690 → 0.9660으로 떨어진다.
4. **가중치는 균등, 멤버 선택은 반분 검증.** 앞 1000건 · 뒤 1000건 양쪽에서 오를 때만 멤버로 채택한다.

- 추론 함수에서 다음 배치 전처리를 백그라운드로 미리 하도록 바꿔 test 추론이 약 10% 빨라졌다.

## 실패 기록

| 시도 | 결과 | 원인·교훈 |
|---|---|---|
| dev.csv를 추가 라벨로 | 사용 불가 | 5명 중 4명 이상 일치 0건. 대회 기준 미달로 폐기된 문항 모음 |
| OCR 매칭 단독 예측 | 49% (자신 있는 13%도 80%) | EasyOCR 인식 오타. 모델(94%)에 못 미침. 앙상블 보조로만 사용 |
| 앙상블 가중치 전수 탐색 | 홀드아웃 0.958 → 반분 검증 0.9525, LB 0.95084 | 2000건으로 가중치 4개를 맞추면 과적합. **균등 평균으로 전환** |
| 7B 홀드아웃 확률 파일 덮어쓰기 | 09/21 16:15 셀 재실행으로 다른 모델 확률로 바뀜 | 수정 시각으로 발견, 09/22 재계산(0.9215)으로 복구. **확률 파일은 save_path 방식으로만 생성** |
| 학습 시 CheckpointError | Qwen3-VL에서 gradient checkpointing 텐서 수 불일치 | `use_cache=False`(text_config 포함) + reentrant 방식으로 해결 |
| 32B 재로드 시 메모리 부족 | 학습 변수들이 이전 모델을 붙잡음 | `load_model`이 학습 변수까지 정리하도록 수정. 안 되면 세션 재시작 |
| TTA (보기 순서 회전 평균) | 단독 0.9555 → 2-way 0.9535 / 4-way 0.9550 | 학습 때 이미 보기를 셔플해서 위치 편향이 없음 |
| 학습 모델에 OCR 텍스트 주입 | 0.9545 (주입 없음 0.9555) | 학습하면 모델이 스스로 읽음. 외부 OCR은 모델보다 못 읽고 위치 정보도 잃음 |
| 32B 해상도 768 → 1024 | 0.9585 → 0.9550 | 학습 후엔 해상도 효과 없음. 단, 앙상블 다양성으로는 기여 |
| 약한 멤버를 센 버전으로 교체 | 7b_zs → 7b_ft: 0.9690 → 0.9660 | 학습하면 다른 학습 모델과 같은 문제를 틀림. 다양성이 떨어짐 |
| PaddleOCR 비교 0/500 | 버그 | `pred_idx == row['answer']`에서 숫자(0~3)와 글자(a~d)를 비교. `"abcd"[pred_idx]`로 수정 필요 |
| 8B 1024 epoch 2 | 학습 중단 | 끊긴 뒤 LoRA 위에 체크포인트를 다시 얹어 평가 → 점수 신뢰도 낮음. 재평가는 새 세션에서 `load_model(adapter=)`로 |
