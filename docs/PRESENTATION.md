## 1장 — 표지

**슬라이드 제목**

텍스트 이미지 VQA — 감자 안심은 감자밭

**슬라이드에 들어갈 내용**

- 부제: 이미지 속 글자를 읽고 4지선다를 푸는 문제
- SSAFY 16기 대전 6반
- 팀원과 역할: 조은아(팀장 · 오답 분석 · 발표) / 김성현(모델 · 공통 노트북 · 앙상블) / 박정연(학습 레시피) / 이희원(OCR 채널)
- 최종 Public LB **0.96336**

**추천 전개 방식**

10초. 팀 소개는 한 문장만 하고 바로 2장으로 넘어간다. 역할은 4장에서 자세히 다루니 여기서는 이름만 읽는다.

**추천 슬라이드 구성**

가운데 큰 제목, 아래 작은 부제. 하단에 팀원 4명을 가로로 나열(이름 + 역할 한 줄). 오른쪽 위 구석에 최종 점수 배지.

**내용 :**

발표의 문을 여는 장이다. 우리가 푼 문제는 "이미지를 보고 질문에 답하는 문제(VQA)"인데, 그중에서도 이미지 안의 글자를 읽어야 풀리는 문제라는 걸 부제로 먼저 깔아둔다.

최종 점수를 표지에 미리 보여주는 이유는, 청중이 "이 팀은 결과가 이 정도구나"를 알고 나서 과정을 들으면 과정 설명에 더 집중하기 때문이다. 역할은 4장에서 흐름도로 다시 나오니 여기서는 가볍게 넘긴다.

## 2장 — 문제 분석

**슬라이드 제목**

문제 분석 — 핵심은 "글자를 정확히 읽는 능력"

**슬라이드에 들어갈 내용**

- train 6,714건 질문 전수 분류 → **90% 이상이 이미지 속 글자 판독**
    - 상호·이름 25.8% / 문구·판독 21.4% / 가격·할인 13.7% …
    - 개수 세기(카운팅) 0.2%
- **보기의 44.8%가 2글자 이내로만 다르다**
    - 예) a) 1,800원 b) 1,300원 c) 1,200원 d) 1,700원
- 그래서 두 갈래로 시도
    - ① 외부 OCR로 글자를 뽑아 모델에게 알려주기
    - ② 모델 자체가 더 잘 읽게 만들기 (큰 모델 · 고해상도 · 학습)

**추천 전개 방식**

60초. "데이터를 먼저 전부 뜯어봤다" → "대부분이 글자 읽기였다" → "보기 차이가 너무 작다(예시를 가리키며)" → "그래서 두 가지 방향을 세웠다" 순서. 마지막 두 갈래는 질문을 던지는 느낌으로 말하고, 답은 6장에서 한다고 예고한다.

**추천 슬라이드 구성**

왼쪽 절반: 질문 유형 비율 가로 막대그래프(상위 5~6개). 오른쪽 위: 보기 예시 한 줄을 큰 글씨로. 오른쪽 아래: ①과 ② 두 개의 화살표 박스.

**내용 :**

이 장은 "우리가 문제를 어떻게 이해했는지"를 보여준다. 강사님이 강조한 "문제 분석"에 해당하고, 발표 전체의 출발점이다.

우리는 모델부터 돌리지 않고, train 6,714건의 질문을 전부 유형별로 분류했다. 질문의 90% 이상이 가게 이름, 간판 문구, 가격, 전화번호, 영업시간처럼 이미지 속 글자를 읽어야 풀리는 문제였다. 1차 대회에 많았던 개수 세기는 0.2%로 거의 없었다.

더 중요한 건 보기끼리의 차이가 매우 작다는 점이다. 보기의 44.8%가 두 글자 이내로만 다르다. 보기가 1,800원 / 1,300원 / 1,200원 / 1,700원이면 숫자 하나만 잘못 읽어도 틀린다. "대충 알아보는 것"이 아니라 "정확히 읽는 것"이 필요한 문제였다.

그래서 두 가지 방향을 세웠다. 하나는 글자 인식 전문 도구(외부 OCR)로 글자를 먼저 뽑아 모델에게 힌트로 주는 방법(희원 담당), 다른 하나는 더 큰 모델 · 더 높은 해상도 · 학습으로 모델 자체가 더 잘 읽게 만드는 방법(성현 · 정연 담당)이다.

어느 쪽이 이겼는지는 6장에서 답한다. 2장에서 이 질문을 미리 던져두는 게 중요하다. 청중이 "OCR 문제라면서 OCR은 왜 효과가 없었냐"고 물을 때, 답이 이미 발표 흐름 안에 들어 있게 된다.

## 3장 — 검증 기준

**슬라이드 제목**

검증 기준부터 세웠다

**슬라이드에 들어갈 내용**

- dev.csv = 정답이 아니라 **교육생 5명의 응답** → 4명 이상 일치 0건 → **사용하지 않음**
- train을 고정 순서로 섞어 **앞 2,000건을 팀 공통 검증셋**으로 고정 (학습 4,714건)
- 4명이 **같은 검증셋** → 누구 모델이든 비교 가능, 결과를 바로 섞을 수 있음
- 오차 ±0.6%p → **이보다 작은 차이는 "차이 없음"으로 판단**

**추천 전개 방식**

60초. "점수를 올리기 전에, 점수를 믿을 수 있게 만드는 것부터 했다"로 시작. dev.csv를 버린 이유 → 대신 만든 검증셋 → 팀 공통 규칙 → 오차 기준 순서. 마지막 문장은 "이 기준 덕분에 뒤에서 '올랐다'는 착각을 여러 번 막았다"로 6·7장을 예고한다.

**추천 슬라이드 구성**

위쪽: train 6,714 막대 하나가 [검증 2,000]과 [학습 4,714] 두 칸으로 나뉘는 그림. 아래 왼쪽: dev.csv에 X 표시 + "5명 응답, 일치 0건". 아래 오른쪽: "±0.6%p 미만 = 차이 없음" 강조 박스.

**내용 :**

이 장은 "실험 전략"의 기초다. 성능을 올리려면 먼저 "올랐는지 아닌지"를 판단할 기준이 있어야 한다.

대회에서 dev.csv라는 검증용 파일을 줬는데, 열어보니 정답이 아니라 교육생 5명이 직접 푼 답이었다. 5명 중 4명 이상 답이 같은 문제가 한 건도 없었다. 이걸 기준으로 쓰면 판단이 틀어지니 과감히 버렸다.

대신 train을 정해진 순서로 섞은 다음, 앞 2,000건을 떼어 검증셋으로 쓰고 나머지 4,714건으로만 학습했다. 중요한 건 이걸 팀 전체 규칙으로 만들었다는 점이다. 네 명이 각자 다른 실험을 해도 모두 같은 2,000건으로 채점하니까, 정연이 만든 모델과 성현이 만든 모델을 바로 비교하고 둘의 결과를 섞어볼 수도 있었다. 7장의 앙상블이 가능했던 게 이 규칙 덕분이다.

2,000건으로 채점하면 운에 따른 오차가 약 ±0.6%p 있다. 그래서 이보다 작은 차이는 "좋아졌다"가 아니라 "차이 없음"으로 보기로 미리 정했다. 어떤 방법이 0.1%p 올랐을 때 "효과 있다"고 착각하고 그 방향에 시간을 쓰는 걸 이 원칙이 여러 번 막아줬다.

## 4장 — 팀 분배와 협업

**슬라이드 제목**

팀 분배와 협업 방식

**슬라이드에 들어갈 내용**

- 역할을 **"재료가 흐르는 순서"**대로 분배
    - 희원(OCR 추출) → 정연(모델 학습) → 성현(앙상블 조합) → 은아(제출 · 오답 분석)
    - 은아의 오답 분석 → 정연 · 희원에게 피드백
- **공통 노트북 1개** 공유 → 같은 코드, 설정값만 바꿔 실험
- 결과 전달 규칙: **파일 경로 + 설정 이름 + 검증 점수**
- 제약: A100 GPU 팀 전체 동시 2대 → 병렬 실험, 결과는 확률 파일로 교환

**추천 전개 방식**

60초. 흐름도를 왼쪽에서 오른쪽으로 따라가며 설명한다. "각자 맡은 게 다음 사람의 재료가 되도록 나눴다"가 핵심 문장. 그다음 공통 노트북과 전달 규칙을 "실수를 줄이는 장치"로 소개하고, GPU 제약은 마지막에 짧게.

**추천 슬라이드 구성**

가운데 크게: 네 명의 이름 박스를 화살표로 잇는 흐름도 (은아 → 정연·희원으로 돌아가는 점선 화살표 포함). 하단: 작은 박스 2개 — "공통 노트북", "전달 규칙 3가지".

**내용 :**

이 장은 강사님이 말한 "팀 분배가 어떤 형태로 이뤄졌는지"에 대한 답이다.

역할을 기능별로 나누기보다 "재료가 흐르는 순서"로 나눴다. 희원이 이미지에서 글자를 뽑아두면(OCR), 정연이 그걸 활용하거나 모델을 학습시키고, 성현은 모든 사람의 모델 결과를 모아 섞어서(앙상블) 제출 파일을 만들고, 은아가 제출하고 틀린 문제를 분석한다. 은아의 분석 결과(어떤 유형을 많이 틀리는지)는 다시 정연과 희원에게 돌아가 다음 실험 방향이 된다. 한 사람의 결과물이 항상 다음 사람의 재료가 되는 구조다.

협업 실수를 줄이려고 두 가지 장치를 두었다. 하나는 공통 노트북이다. 기본 코드를 하나 만들어 공유하고, 각자 복사해서 설정값(모델 크기, 해상도, 학습 데이터 양)만 바꿔 실험했다. 코드가 사람마다 다르면 결과 차이가 설정 때문인지 코드 때문인지 알 수 없기 때문이다. 다른 하나는 결과 전달 규칙이다. 결과를 넘길 때 파일 위치, 설정 이름, 검증 점수 세 가지를 항상 같이 보냈다.

팀 전체가 A100 GPU를 동시에 2대까지만 쓸 수 있었다. 그래서 각자 다른 실험을 나눠 돌리고, 결과는 확률 파일로만 주고받았다.

## 5장 — 기술적 접근

**슬라이드 제목**

기술적 접근 — 모델 · 추론 · 학습

**슬라이드에 들어갈 내용**

- 모델: 베이스라인 Qwen2.5-VL-3B → Qwen2.5-VL-7B → **Qwen3-VL 8B / 32B**
    - 학습 없이 (768px 기준): 3B 0.860 → 8B 0.9295 → 32B 0.9375
- 추론: 답을 생성하지 않고 **a/b/c/d 네 글자의 확률만 비교**
    - 형식 오류 **0건**, 확률을 앙상블에 재사용
- 학습: 4bit 압축 + 일부만 학습(QLoRA) + **보기 순서 무작위 섞기**
    - 학습 후: 8B 0.9375 → **0.9555** (1024px) / 32B 0.9375 → **0.9585** (768px)

**추천 전개 방식**

45초. 세 줄(모델 → 추론 → 학습)을 위에서 아래로 빠르게. 기본 개념은 한 문장씩만(강의 자료 "모두가 아는 건 한 문장으로"). 숫자는 막대그래프로 보여주고 말로는 "학습으로 약 2%p 올랐다" 정도만.

**추천 슬라이드 구성**

왼쪽: 세 줄 요약(모델 / 추론 / 학습) 각각 아이콘 + 한 줄. 오른쪽: 모델별 정확도 막대그래프, 학습 전(연한 색) / 학습 후(진한 색).

**내용 :**

우리가 쓴 기술을 짧게 정리하는 장이다. 다른 팀도 비슷한 기술을 썼을 테니 길게 설명하지 않고, 왜 그걸 골랐는지만 말한다.

모델은 공식 베이스라인인 Qwen2.5-VL-3B에서 시작해, 같은 계열의 7B를 거쳐 더 크고 최신인 Qwen3-VL로 옮겼다. 학습 없이 풀게 하면(768px 기준) 3B는 86% 정도였는데, Qwen3-VL 8B는 92.95%, 32B는 93.75%가 됐다. 7B는 이후 앙상블에서 "다른 계열 모델"로 다시 쓰인다(7장). 글자를 읽는 문제라 모델이 클수록 잘 읽었다.

추론 방식을 바꾼 게 중요한 선택이었다. 보통은 모델에게 답을 문장으로 쓰게 하는데, 그러면 가끔 "정답은 b입니다"처럼 형식을 안 지켜서 채점이 깨진다. 우리는 모델이 a, b, c, d 각각에 주는 확률만 보고 가장 높은 걸 골랐다. 형식 오류가 0건이 됐고, "a는 70%, b는 20%" 같은 확률이 남기 때문에 여러 모델의 확률을 평균 내는 앙상블에 그대로 쓸 수 있었다.

학습은 GPU 메모리를 아끼려고 모델을 4bit로 압축하고 일부 파라미터만 학습시키는 QLoRA를 썼다. 학습할 때 보기 순서를 매번 무작위로 섞어서, 모델이 "정답은 주로 a에 있더라" 같은 위치 습관을 배우지 못하고 내용만 보게 했다. 이 셔플은 6장에서 TTA가 효과 없었던 이유와도 연결된다. 학습 결과 8B는 1024px에서 93.75% → 95.55%, 32B는 768px에서 93.75% → 95.85%로 올랐다. (숫자를 비교할 때는 해상도를 같이 적어야 헷갈리지 않는다.)

## 6장 — 시행착오 ① (발표 핵심)

**슬라이드 제목**

시행착오 ① — 효과가 사라진 기법들

**슬라이드에 들어갈 내용**

| 시도 | 결과 | 원인 |
|---|---|---|
| 앙상블 가중치 최적화 | 검증 0.958 → LB 0.95084 | 검증셋에 과적합 → 균등 평균으로 전환(LB 0.95174) |
| 보기 순서 바꿔 반복 풀기(TTA) | 0.9555 → 0.9550 | 학습 때 이미 셔플 → 위치 편향 없음 |
| 외부 OCR 글자를 질문에 주입 | 저해상도·학습 전 +1.2%p → 고해상도 +0.25%p → 학습 후 −0.1%p | 외부 OCR 단독 49% vs 모델 93%+ → 모델이 더 잘 읽음 |
| 해상도 768 → 1024 | 학습 전 +0.8%p → 32B 학습 후 효과 없음 | 위와 같은 패턴 |

**결론 (크게):** 입력을 보강하는 기법은, 모델이 스스로 잘 읽게 되는 순간 효과가 사라졌다

**추천 전개 방식**

75초, 발표에서 가장 중요한 장. 표를 한 줄씩 읽지 말고 "시도 → 기대 → 실제 결과 → 우리가 찾은 원인" 순서로 이야기처럼. OCR 줄에서 2장의 질문("OCR 문제인데 OCR은?")에 답한다고 명확히 연결한다: "2장에서 두 갈래로 시도했다고 했는데, 결과는 ②가 이겼습니다." 마지막에 결론 한 문장을 천천히.

**추천 슬라이드 구성**

위쪽 70%: 시도 / 결과 / 원인 3열 표(4줄). 오른쪽 작은 그래프: OCR 효과가 +1.2 → +0.25 → −0.1로 떨어지는 계단 그래프. 하단 전체 폭: 굵은 결론 한 줄, 폰트 크게.

**내용 :**

이 장이 발표의 핵심이다. 강사님 자료에 "못한 건 숨기기보다 '시도 → 원인 파악 → 다음 선택'으로 녹여라"라고 되어 있었는데, 이 장이 정확히 그것이다.

첫 번째는 앙상블 가중치 최적화다. 모델마다 비중을 다르게 주면 더 좋을 것 같아 검증셋에서 가장 점수가 높은 비중을 찾았다. 검증 점수는 95.8%로 좋아 보였지만, 실제 제출하니 0.95084로 오히려 떨어졌다. 2,000건에 너무 딱 맞춰서 처음 보는 데이터에서는 안 먹힌 것이다(과적합). 모든 모델을 같은 비중으로 섞는 균등 평균으로 바꾸자 0.95174로 올랐고, 이후 모든 앙상블은 균등 평균만 썼다.

두 번째는 TTA다. 보기 순서를 바꿔 여러 번 풀게 하고 평균을 내는 방법인데 효과가 없었다. 학습할 때 이미 보기 순서를 섞었기 때문에 모델에게 위치 습관이 없었고, 순서를 바꿔 풀어도 같은 답이 나왔던 것이다.

세 번째가 가장 중요한 OCR 주입 실험이고, 2장에서 던진 질문에 대한 답이다. 저해상도 이미지에 학습 전 모델일 때는 OCR 글자를 넣어주면 1.2%p나 올랐다. 그런데 해상도를 올리니 0.25%p로 줄었고, 학습까지 시키니 효과가 없어졌다(−0.1%p, 오차 범위 안).

원인은 외부 OCR이 모델보다 글자를 못 읽었기 때문이다. 외부 OCR 결과만으로 보기를 맞히면 49%인데, 모델은 혼자서도 93% 이상이었다. 또 외부 OCR은 글자를 위치 정보 없이 한 줄로 쏟아내서, 간판에 가격이 여러 개 있으면 어느 메뉴의 가격인지 알 수 없다. 모델이 약할 때는 이 힌트가 도움이 됐지만, 모델이 스스로 잘 읽게 되자 더 못 읽는 도구의 결과는 필요 없어졌다. "가장 잘 읽는 OCR은 VLM 자신이었다"는 결론이고, 희원의 작업은 실패가 아니라 이 결론에 도달하게 해준 실험이다.

네 번째 해상도도 같은 패턴이었다. 학습 전에는 해상도를 올리면 0.8%p 올랐지만, 32B 모델을 학습시킨 뒤에는 차이가 없었다. 네 가지를 모으면 "입력 보강 기법은 모델이 스스로 잘 읽게 되는 순간 효과가 사라진다"로 정리된다. 이 발견 덕분에 남은 시간을 입력 보강이 아니라 모델 조합(7장)에 쓰기로 방향을 바꿨다.

**질문 대비 — "OCR 문제라면서 OCR은 왜 효과가 없었나요?"**

"네, 문제 자체는 글자 판독 문제가 맞습니다. 그래서 처음엔 외부 OCR로 글자를 뽑아 모델에게 알려주는 방법을 시도했는데, 외부 OCR만으로 푼 정확도가 49%였고 VLM은 혼자서도 93% 이상이었습니다. 결국 가장 잘 읽는 OCR은 VLM 자신이었고, 그래서 모델이 더 잘 읽게 만드는 쪽에 집중했습니다. 외부 OCR은 모델이 약했던 초반엔 1.2%p를 보탰지만, 모델이 강해지면서 기여가 사라졌습니다."

## 7장 — 시행착오 ② (발표 핵심)

**슬라이드 제목**

시행착오 ② — 앙상블은 "센 모델"보다 "다른 모델"

**슬라이드에 들어갈 내용**

- 가중치는 모두 같게(1:1:1:1) — 대신 **"누구를 넣을지"만 엄격한 규칙으로 결정**
- 후보 모델 8개 → **"검증 앞 1,000건 · 뒤 1,000건 모두에서 오를 때만 채택"** 규칙으로 선택
    - 6장의 과적합을 반복하지 않기 위한 장치
- 7B는 나머지(Qwen3)와 세대가 다른 Qwen2.5 계열 → 다양성 확보용 후보로 포함
- 더 센 모델로 교체했더니 **하락**
    - 7B 학습 전(0.9215) → 학습 후(0.9490): 앙상블 0.9690 → **0.9660**
    - 8B 2,000건 학습(0.9415) → 4,714건(0.9465): 0.9690 → **0.9675**
- 같은 계열 모델을 여러 개 넣어도 하락 (8B 3개: 0.9645 → 0.9610)

**결론 (크게):** 앙상블에 필요한 건 센 모델이 아니라 다르게 틀리는 모델이다

**추천 전개 방식**

60초. 첫 문장은 6장과 잇는다: "가중치를 없앴다고 해서 아무 모델이나 넣은 건 아닙니다. 비중은 모두 같게 두고, 들어올 멤버만 엄격하게 골랐습니다." 그다음 "상식적으로 더 센 모델을 넣으면 오를 거라 생각했다"로 기대를 먼저 세운 다음, 숫자로 뒤집는다. 원인 설명 후 결론 한 문장. 6장과 같은 흐름(시도 → 뜻밖의 결과 → 원인 → 결론)으로 말하면 기억에 남는다.

**추천 슬라이드 구성**

위쪽: 채택 규칙을 작은 박스로 (앞 1,000 ✓ + 뒤 1,000 ✓ = 채택). 가운데: 교체 전/후 막대 2쌍 — 단독 점수는 올랐는데(작은 ↑) 앙상블 점수는 내려간(큰 ↓) 대비를 색으로 강조. 하단 전체 폭: 굵은 결론 한 줄.

**내용 :**

6장에서 입력 보강 대신 모델 조합에 집중하기로 했다. 이 장은 그 조합에서 배운 것이다.

학습시킨 모델이 8개까지 늘어나 어떤 조합이 가장 좋은지 찾아야 했다. 6장에서 가중치를 없앴기 때문에 모든 멤버의 비중은 1:1:1:1로 같다. 대신 "어떤 모델을 멤버로 넣을지"를 정해야 했는데, 여러 조합 중 검증 점수가 제일 높은 걸 고르면 6장처럼 또 과적합될 수 있다. 그래서 규칙을 하나 만들어 코드로 박아두었다. 검증셋 2,000건을 앞 1,000건과 뒤 1,000건으로 나누고, 양쪽 모두에서 점수가 오를 때만 그 모델을 추가하는 것이다. 한쪽에서만 오르면 운일 수 있으니까.

후보에는 5장에서 거쳐간 Qwen2.5-VL-7B도 넣었다. 나머지 모델은 모두 Qwen3 계열인데 7B만 세대가 다른 Qwen2.5라서, 다른 방식으로 틀려줄 것을 기대한 것이다.

이 과정에서 예상과 반대되는 결과가 나왔다. 앙상블에 들어가 있던 7B 모델은 학습을 안 한 버전이라 단독 점수가 92%로 약했다. 그래서 학습시켜 95%로 올린 버전으로 바꿨는데, 앙상블 점수는 오히려 96.9%에서 96.6%로 떨어졌다. 8B도 2,000건으로 학습한 버전을 4,714건으로 더 학습시켜 바꿨는데 마찬가지로 떨어졌다. 같은 8B 계열 모델을 세 개 넣었을 때도 떨어졌다.

원인은 "다르게 틀리는가"였다. 앙상블은 여러 모델이 투표하는 것과 비슷해서, 한 모델이 틀려도 다른 모델들이 맞히면 정답이 나온다. 그런데 모델들을 같은 데이터로 학습시키면 비슷한 문제를 같이 틀리게 된다. 학습 안 한 7B는 약하지만 다른 모델들과 틀리는 문제가 달라서 오히려 가치가 있었다. 같은 계열을 여러 개 넣으면 그 계열의 표가 너무 많아져 투표가 한쪽으로 쏠린다.

그래서 최종 구성에는 학습 안 한 7B, 8B, 그리고 해상도가 다른 32B 두 개가 들어갔다. 같은 32B라도 해상도를 다르게 하면 보는 방식이 달라져 서로 다른 문제를 틀렸고, 그래서 둘을 함께 넣었을 때 점수가 올랐다.

## 8장 — 결과와 회고

**슬라이드 제목**

결과와 회고

**슬라이드에 들어갈 내용**

- 최종 Public LB **0.96336** (검증 0.9690)
    - 7B(학습 전) + 8B(학습) + 32B(학습·768) + 32B(학습·1024) 균등 평균
- 점수 변화: 0.86267 → 0.91957 → … → 0.95174 → 0.95889 → 0.95978 → **0.96336**
    - 참고: 1차 대회 최종 0.91407
- 한정된 GPU 안에서 실험마다 기대 효과와 비용을 비교해 순서 결정
- 모든 실험(성공·실패)을 기록 → 발표의 모든 숫자는 실측값
- 남은 약점: 위치·주소 유형(0.87~0.91) — "왼쪽/오른쪽/방면" 같은 공간 판단

**추천 전개 방식**

60초. 최종 점수 → 그래프를 따라 "여기서 모델 교체, 여기서 균등 앙상블, 여기서 32B 추가"로 짧게 → 우리가 일한 방식(제약 속 판단, 기록) → 약점과 다음 시도 → "감사합니다". 마지막 문장은 "점수를 올린 것보다, 올릴 때마다 근거를 남긴 게 우리 팀의 방식이었습니다."

**추천 슬라이드 구성**

위쪽 60%: 점수 변화 꺾은선 그래프. 주요 점에만 라벨(베이스라인 / 균등 앙상블 전환 / 32B 학습 / 32B 고해상도 추가). 아래 왼쪽: 최종 구성 4개 모델 아이콘. 아래 오른쪽: "남은 약점: 위치·주소" 작은 박스.

**내용 :**

마지막 장이다. 결과를 보여주고, 우리가 어떻게 일했는지로 마무리한다.

최종 제출 점수는 0.96336이고, 학습 안 한 7B, 학습한 8B, 해상도가 다른 학습된 32B 두 개를 같은 비중으로 섞은 결과다. 베이스라인 0.86267에서 시작해 큰 모델로 바꾸고, 학습시키고, 균등 앙상블로 전환하고, 32B를 추가하면서 계단식으로 올라갔다. 1차 대회 최종 점수 0.91407보다도 한참 높다.

점수 외에 강조할 건 두 가지다. 하나는 제약 속의 판단이다. GPU 사용량이 한정돼 모든 실험을 다 할 수 없었고, 실험마다 "얼마나 오를 것 같은지, 비용이 얼마인지"를 비교해 순서를 정했다. 예를 들어 YOLO 같은 물체 탐지 모델을 붙이자는 제안도 있었는데, 질문의 90%가 글자 판독이고 입력 보강 기법이 효과 없다는 걸 이미 확인했기 때문에 하지 않기로 했다. 다른 하나는 기록이다. 성공한 실험뿐 아니라 실패한 실험도 전부 점수와 함께 기록했고, 그래서 이 발표의 모든 숫자는 실제로 측정한 값이다.

아쉬운 점도 솔직하게 말한다. 유형별로 보면 위치·주소 문제(예: "출구는 어느 방향인가")의 정확도가 87~91%로 가장 낮았다. 글자는 읽는데 "왼쪽/오른쪽/방면" 같은 공간 판단을 헷갈리는 것이다. 시간이 더 있었다면 이 유형을 위한 데이터 보강이나 추론 방식 개선을 시도했을 것이다.

마지막 문장은 "점수를 올린 것보다, 올릴 때마다 근거를 남긴 게 우리 팀의 방식이었습니다"로 끝낸다.

## 전체 발표 흐름 (긴 글 버전)

우리 팀 "감자 안심은 감자밭"이 맡은 문제는 이미지와 한국어 질문, 네 개의 보기가 주어졌을 때 정답을 고르는 문제였다. 겉으로는 일반적인 시각 질의응답(VQA) 문제처럼 보였지만, 우리는 모델을 돌리기 전에 먼저 데이터를 전부 들여다보는 것부터 시작했다.

train 데이터 6,714건의 질문을 전부 유형별로 분류해 보니, 90% 이상이 이미지 속 글자를 읽어야만 풀 수 있는 문제였다. 가게 이름, 간판 문구, 가격, 전화번호, 영업시간 같은 것들이었고, 1차 대회에 많았던 개수 세기 문제는 0.2%로 거의 사라져 있었다. 더 까다로운 점은 보기끼리의 차이가 매우 작다는 것이었다. 보기의 44.8%가 두 글자 이내로만 달랐다. 1,800원, 1,300원, 1,200원, 1,700원처럼 숫자 하나만 잘못 읽어도 틀리는 구조였다.

그래서 우리는 이 문제의 핵심을 "글자를 정확히 읽는 능력"으로 정의했고, 두 갈래로 접근했다. 하나는 글자 인식 전문 도구인 외부 OCR로 글자를 먼저 뽑아 모델에게 힌트로 주는 것이고, 다른 하나는 더 큰 모델, 더 높은 해상도, 학습을 통해 모델 자체가 더 잘 읽게 만드는 것이었다.

본격적으로 실험하기 전에 검증 기준을 세웠다. 대회에서 제공한 dev.csv는 정답이 아니라 교육생 5명의 응답이었고, 5명 중 4명 이상이 같은 답을 고른 문제가 한 건도 없었다. 이 파일로는 모델 성능을 믿을 수 없다고 판단해 사용하지 않았다. 대신 train 데이터를 정해진 순서로 섞은 뒤 앞 2,000건을 떼어 검증셋으로 삼고, 나머지 4,714건으로만 학습했다.

이 검증셋을 팀 전원이 똑같이 쓰도록 규칙으로 정했다. 그 덕분에 누가 만든 모델이든 같은 기준으로 비교할 수 있었고, 서로의 결과를 바로 섞어볼 수도 있었다. 또 검증셋 2,000건의 오차가 약 ±0.6%p라는 점을 계산해, 그보다 작은 차이는 "차이 없음"으로 판단한다는 원칙도 미리 세웠다.

팀 역할은 재료가 흐르는 순서대로 나눴다. 이희원이 이미지에서 글자를 추출하면, 박정연이 모델을 학습시키고, 김성현이 모든 모델의 결과를 모아 앙상블로 조합하고, 조은아가 제출하고 틀린 문제를 분석해 다시 정연과 희원에게 전달했다. 협업 실수를 줄이려고 공통 노트북 하나를 만들어 모두가 같은 코드에서 설정값만 바꿔 실험했고, 결과를 넘길 때는 파일 위치, 설정 이름, 검증 점수 세 가지를 항상 함께 전달했다. GPU는 팀 전체가 동시에 두 대까지만 쓸 수 있어서, 각자 다른 실험을 병렬로 돌리고 결과는 확률 파일로만 주고받았다.

기술적으로는 세 가지를 선택했다. 먼저 모델을 공식 베이스라인인 Qwen2.5-VL-3B에서 같은 계열의 7B를 거쳐, 더 크고 최신인 Qwen3-VL 8B와 32B로 바꿨다. 학습 없이도(768px 기준) 정확도가 86%에서 93%대로 올랐다. 다음으로 모델에게 답을 문장으로 생성시키는 대신 a, b, c, d 네 글자에 주는 확률만 비교하는 방식으로 바꿨다. 형식 오류가 사라졌고, 각 보기의 확률이 남아서 나중에 앙상블에 그대로 쓸 수 있었다. 마지막으로 모델을 4bit로 압축하고 일부 파라미터만 학습시키는 QLoRA를 썼는데, 학습할 때마다 보기 순서를 무작위로 섞어 모델이 정답 위치에 대한 습관 없이 내용만 보도록 했다. 학습 결과 8B는 1024px에서 95.55%, 32B는 768px에서 95.85%까지 올랐다.

이 과정에서 가장 많이 배운 건 실패한 실험들이었다. 앙상블에서 모델마다 비중을 다르게 주려고 검증셋에서 최적의 비중을 찾았는데, 검증 점수는 95.8%였지만 실제 제출 점수는 0.95084로 오히려 떨어졌다. 검증셋 2,000건에 과하게 맞춰진 것이었다. 모든 모델을 같은 비중으로 섞는 균등 평균으로 바꾸자 제출 점수가 0.95174로 올랐고, 이후로는 균등 평균만 썼다. 보기 순서를 바꿔 여러 번 풀게 하는 TTA도 효과가 없었는데, 학습 때 이미 보기를 섞었기 때문에 모델에게 위치 편향이 없었던 것이 원인이었다.

가장 의미 있었던 실패는 OCR이었다. 저해상도 이미지와 학습 전 모델에서는 외부 OCR 글자를 질문 앞에 붙여주자 정확도가 1.2%p 올랐다. 그런데 해상도를 올리자 그 효과가 0.25%p로 줄었고, 학습까지 시키자 사라졌다. 외부 OCR 결과만으로 보기를 맞히면 49%였는데, 모델은 혼자서도 93% 이상이었다. 외부 OCR은 모델보다 글자를 못 읽는 도구였고, 글자를 위치 정보 없이 한 줄로 늘어놓기 때문에 간판에 가격이 여러 개 있으면 어느 메뉴의 가격인지도 알 수 없었다. 모델이 약할 때는 이 힌트가 도움이 됐지만, 모델이 스스로 잘 읽게 되자 필요가 없어진 것이다. 해상도를 올리는 것도 같은 패턴이었다. 학습 전에는 0.8%p를 올렸지만 학습된 32B 모델에서는 차이가 없었다.

이 네 가지를 모아 우리는 "입력을 보강하는 기법은 모델이 스스로 잘 읽게 되는 순간 효과가 사라진다"는 결론을 내렸다. 문제의 핵심이 글자 판독이라는 건 맞았지만, 가장 잘 읽는 OCR은 결국 VLM 자신이었다. 이 결론에 따라 남은 시간을 입력 보강이 아니라 모델 조합에 쓰기로 방향을 바꿨다.

모델 조합에서도 예상과 다른 것을 배웠다. 학습시킨 모델이 여덟 개까지 늘어나 어떤 조합이 좋은지 찾아야 했는데, 멤버의 비중은 모두 같게 두되, 누구를 멤버로 넣을지 정할 때 가중치 탐색에서 겪은 과적합을 반복하지 않기 위해 규칙을 하나 만들었다. 후보에는 나머지와 세대가 다른 Qwen2.5 계열 7B도 다양성을 위해 포함했다. 검증셋을 앞 1,000건과 뒤 1,000건으로 나누고, 양쪽 모두에서 점수가 오를 때만 그 모델을 추가하는 것이다.

이 과정에서 앙상블에 있던 학습 안 한 7B 모델(92.15%)을 학습시킨 버전(94.90%)으로 바꿨더니, 단독 점수는 올랐는데 앙상블 점수는 96.90%에서 96.60%로 떨어졌다. 8B 모델을 더 많은 데이터로 학습시켜 바꿨을 때도, 같은 8B 계열을 여러 개 넣었을 때도 마찬가지로 떨어졌다. 모델들을 같은 데이터로 학습시키면 비슷한 문제를 같이 틀리게 되고, 그러면 여러 모델이 투표하는 앙상블의 장점이 사라진다. 학습 안 한 7B는 약하지만 다른 모델들과 다른 문제를 틀렸기 때문에 오히려 가치가 있었다. 우리는 "앙상블에 필요한 건 센 모델이 아니라 다르게 틀리는 모델"이라는 결론을 얻었고, 같은 32B라도 해상도를 다르게 한 두 모델을 함께 넣었을 때 점수가 오른 것도 같은 원리로 설명됐다.

최종 제출은 학습 안 한 7B, 학습한 8B, 해상도가 다른 학습된 32B 두 개를 같은 비중으로 섞은 것으로, Public LB 0.96336을 기록했다. 베이스라인 0.86267에서 시작해 큰 모델로의 교체, 학습, 균등 앙상블로의 전환, 32B 추가를 거치며 단계적으로 올라왔고, 1차 대회 최종 점수인 0.91407도 크게 넘었다.

한정된 GPU 안에서 실험마다 기대 효과와 비용을 비교해 순서를 정했고, 물체 탐지(YOLO) 같은 제안도 앞선 실험 결과를 근거로 하지 않기로 판단했다. 성공한 실험과 실패한 실험을 모두 점수와 함께 기록했기 때문에 이 발표의 모든 숫자는 실측값이다. 남은 약점은 위치·주소 유형으로, 정확도가 87~91%로 가장 낮았다. 글자는 읽지만 왼쪽, 오른쪽, 방면 같은 공간 판단을 헷갈리는 문제로, 시간이 더 있었다면 이 부분을 개선했을 것이다.

우리 팀이 3일 동안 한 일을 한 문장으로 정리하면, 점수를 올린 것보다 올릴 때마다 근거를 남긴 것이다.
